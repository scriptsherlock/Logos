1) Problem framing & clarity

The goal of this project is to build a sentiment analysis system that predicts whether a movie review expresses positive or negative sentiment. I treat this as a binary classification problem because the chosen dataset provides two labels and because the main question is whether a review recommends the movie overall. I focus on written English reviews where language is informal but mostly grammatical, and the model must handle negation, intensifiers (“very”), and mixed opinions (“great acting but boring plot”).

Success is measured by how accurately and reliably the model classifies unseen reviews. Because class balance and error types matter (e.g., systematically misclassifying negative reviews as positive), I evaluate performance using not only accuracy but also precision, recall, and F1, plus a confusion matrix.

2) Dataset understanding & data literacy

I use the IMDB movie reviews dataset (binary sentiment). It contains 50,000 labeled reviews split evenly into train and test sets (25k/25k). Labels are balanced: 50% positive, 50% negative.

To understand the data, I inspected random samples and noticed:

Reviews vary widely in length: from one-line reactions (“Loved it.”) to long paragraphs with detailed critique.
Many reviews contain mixed sentiment, but the label represents the overall stance. For example, “The acting is great but the story is awful” can still be labeled negative if the reviewer concludes they disliked the movie.
Common linguistic challenges include negation (“not good”), sarcasm (“what a masterpiece… said no one ever”), and domain-specific vocabulary (film terms, actor names).

Examples (paraphrased):

Positive: “The pacing was excellent and the ending felt earned.”
Negative: “Strong cast, but the script is a mess and drags endlessly.”

Potential dataset limitations:

Labels may reflect the reviewer’s final verdict rather than sentence-level sentiment, which can confuse models on mixed opinions.
Language is movie-review specific; performance may drop on other domains (tweets, product reviews).
Some reviews include spoilers, rhetorical questions, or slang.
3) Methodology & technical depth

I build two systems: a simple baseline and an improved model.

3.1 Baseline: Logistic Regression with Bag-of-Words

Idea: Represent each review by word counts and learn a linear decision boundary.

Vectorizer: CountVectorizer (unigrams)
Model: Logistic Regression (L2 regularization)

Why this baseline:

It is simple, fast, and provides a strong reference point.
It works well when sentiment is signaled by individual words (“great”, “terrible”) even without word order.
3.2 Improved model: TF-IDF + Linear SVM

Idea: Use TF-IDF to downweight very common words and emphasize discriminative terms, then use a linear SVM classifier which often performs well on sparse text features.

Vectorizer: TfidfVectorizer (unigrams + bigrams)
Model: Linear SVM (LinearSVC)

Why this is an improvement:

TF-IDF reduces the effect of frequent but uninformative words.
Bigrams help capture short phrases including negation patterns (“not good”, “no longer”).
Linear SVM is robust for high-dimensional sparse features and can yield stronger margins than logistic regression.
3.3 Reproducibility details
Train/test split: the dataset-provided split (25k train, 25k test).
Preprocessing: described below.
Hyperparameters:
Logistic Regression: C=1.0, solver liblinear
TF-IDF: ngram_range=(1,2), min_df=2, max_df=0.95
Linear SVM: default C=1.0
All models trained on the same training set and evaluated on the same test set.
4) Preprocessing & feature representation
4.1 Preprocessing choices

I used light preprocessing to avoid removing useful sentiment cues:

Lowercasing
Remove HTML tags (IMDB reviews often contain <br />)
Keep punctuation as raw text (because exclamation marks can correlate with strong sentiment)
No stopword removal (words like “not” are crucial)
No stemming/lemmatization (I found that aggressive normalization can sometimes reduce nuance; also TF-IDF handles variants reasonably)
4.2 Feature representation
Baseline: Bag-of-words word counts (unigram counts).
Improved: TF-IDF features with unigrams and bigrams.

Tradeoffs:

Bag-of-words is simpler but treats all words equally; common words can dominate.
TF-IDF reduces dominance of frequent words and often improves generalization.
Bigrams increase feature space size but capture short context important for negation and common phrases.

6) Error analysis & iteration

I analyzed misclassified examples and found three recurring failure patterns:

Failure Case 1: Sarcasm / irony

Example (paraphrased):
“Sure, if you enjoy watching paint dry, this is the film for you.”
The model often predicts positive due to words like “enjoy,” but the meaning is negative.

Proposed improvement:

Consider adding features for sarcasm cues (quotation marks, contrast markers).
Try a transformer-based model (e.g., DistilBERT) which may capture deeper semantics.
Failure Case 2: Negation with long distance scope

Example (paraphrased):
“I thought it would be good, but it’s not something I’d recommend.”
The presence of “good” can mislead sparse models when negation/contrast occurs later.

Proposed improvement:

Use bigger n-grams or dependency-aware features.
Use a model that accounts for sequence structure (transformer/RNN).
Failure Case 3: Mixed reviews with a final verdict

Example (paraphrased):
“The acting is great, visuals are stunning, but the plot collapses. Overall, disappointing.”
The model sometimes predicts positive because positive phrases dominate earlier.

Proposed improvement:

Weight later sentences more heavily (heuristic).
Segment the review and classify sentence-level sentiment then aggregate with a learned rule.
Iteration I tried

I added bigrams and tuned TF-IDF thresholds (min_df, max_df), which helped on negation cases like “not good” but didn’t fully solve sarcasm.

7) Communication & structure

This report is structured by rubric criteria and includes model configurations, metrics, and error analysis. If I were presenting to a non-technical stakeholder, I would summarize the key result as:

“A TF-IDF + Linear SVM model achieved ~90% accuracy on IMDB movie reviews and shows fewer obvious mistakes than the baseline, but it still struggles with sarcasm and complex mixed sentiment.”

8) Responsible communication & limitations

Limitations and risks:

Domain specificity: IMDB reviews differ from tweets or product reviews; performance may not transfer.
Label noise: Some reviews are ambiguous or contain both positive and negative statements; labels reflect overall verdict, which may be subjective.
Bias and representativeness: Reviews reflect the writing style of IMDB users and may not represent broader populations or languages.
Overclaiming risk: A 90% accuracy model still misclassifies ~1 in 10 reviews; it should not be used for high-stakes decisions without further validation.

Future work:

Test on at least one other dataset (e.g., Amazon reviews) to measure generalization.
Compare against a lightweight transformer baseline (DistilBERT) and evaluate tradeoffs (accuracy vs latency/cost).
Add calibration or confidence estimates to communicate uncertainty, especially on ambiguous reviews.
Conclusion

The baseline logistic regression model performs strongly, but the TF-IDF + Linear SVM model improves results across all metrics and reduces both types of classification errors. Error analysis shows remaining weaknesses in sarcasm, long-distance negation, and mixed-sentiment structure. With additional modeling (transformers) or smarter aggregation strategies, these failure cases could be reduced, while maintaining responsible claims about where the model is expected to work well and where it may fail.
